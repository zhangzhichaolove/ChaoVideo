# 分集地址接口契约

这是客户端已支持的增量契约，不代表现有生产服务已经返回该字段。无需新建端点；推荐、列表、搜索及分类返回的 `VideoRes` 均可使用。

## 响应示例

```json
{
  "success": true,
  "result": {
    "records": [
      {
        "id": "SERIAL",
        "title": "连续剧",
        "episodes": 2,
        "video": "media/episode_1.mp4",
        "episodeUrls": [
          "media/episode_1.mp4?token=TOKEN",
          "media/finale.m3u8?token=TOKEN"
        ]
      }
    ]
  }
}
```

## 确定规则

- `episodeUrls` 是按集序排列的字符串数组，数组第 1 项对应第 1 集。地址可以是绝对 HTTP(S) URL 或相对地址；相对地址按**发起该请求的 API 基址**解析，不按当前设置、影片 `video` 地址或 CDN 主机解析。
- 数组存在时，数组长度决定可选集数，覆盖旧 `episodes`，每集只使用对应地址。不会拼接 `_1`，不会补齐服务端未返回的集，也不会在某项播放失败时回退到推导地址。
- 缺省或 `null` 表示旧契约，继续使用 `episodes` + `video` 的文件名规则；明确的 `[]` 表示没有分集，按 `video` 播放普通影片。非空数组可不提供 `video`，但为兼容旧客户端建议在过渡期保留旧字段。
- 数组内只接受非空字符串，解析后必须为 HTTP(S) 地址。数字、布尔值、对象、空项及非 HTTP(S) 地址触发请求失败，沿用列表的错误/重试路径，不静默过滤造成集序偏移。连接测试也校验新字段。
- `id` 应在同一 API 来源内稳定且唯一。每集历史按“来源 + 影片 ID + 1-based 集序”保存；**已发布集序必须保持不变，只追加新集或原位更新 URL，不能通过删项/重排移动已有集号**。需要任意重排、插入特别篇或删除中间集的服务端，应先协商独立 episode ID 契约；当前客户端不臆测这些映射。
- URL 可更新签名，不改变同源影片 ID/集序的进度。客户端保存的是最近收到的地址列表，尚无按 ID 刷新剧集详情/续签的端点；旧收藏中已过期的签名需要从服务端列表重新获取，客户端不会生成签名。
- 没有影片 ID 时仍使用源内 URL 回退，签名 URL 变化后的稳定身份不作保证。新服务应提供稳定 ID。

## 持久化与兼容

- Parcelable 保留有序数组；Room v4 增加可空 `episodeUrlsJson`，收藏和历史保存完整列表及原始来源。已有 v1→v2→v3→v4 迁移链。
- v3→v4 只增列，不重写来源、主键、收藏或分集进度。旧行新列为 `null`，不批量生成虚假的分集 URL。
- 缺少新字段的旧文件名规则保留，并修正只改 URL 路径、不改查询参数或片段。对路径绑定的服务端签名，这种旧推导仍可能失效，推荐改为明确列表。
- 在线选集、全屏选集、自然播放结束后自动下一集、续播、下载准备和投屏共用当前集的实际 URL；没有新增服务端能力，也没有声称电视已通过互操作验收。

## 验证

- JVM：数组优先级、空/缺省/非法字段、查询参数与片段、来源绑定、Parcelable、Room 收藏更新及进度保持、v1/v2/v3 升级。
- 专用模拟器执行 `scripts/verify-playback.sh emulator-5580`：真实 Retrofit 接收不规则路径，GSY 全屏 1→3→1→2 切集，保存并从第 2 集续播，真实解码完成后自动播放第 3 集；核对服务器收到完整查询参数且未请求推导地址。
- `scripts/verify-playback-release.sh emulator-5580` 的样本只提供明确的相对分集地址，旧 `video` 指向不存在的文件，确认实际混淆 Release 使用新契约；结束时恢复 Debug，非正式签名产物。

以上脚本仅用于可丢弃模拟器，不用于个人手机或个人数据。
